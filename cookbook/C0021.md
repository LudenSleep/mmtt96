# Draft comments written away from the listing are wrong about half the time

Symptom: region plate/eol comments drafted by an expert from memory, summaries or a skim read state counts, ranges,
strides, axes, sortedness or "same as sibling X" claims that the code does not show. Phase 1.7 wave 1: 23 of 42 draft
comments (55%) were wrong or inexact (9 factual errors in one large region alone).

Cause: the drafter summarises intent, not the instructions; plausible generalisations (a loop "clears 512 words",
"sorted by y", "same as slotpair4_a") are not checked against the operands.

Fix: the comment writer works against `db.py listing <region>` in the same run (coder, not expert drafts); every countable
claim (count, range, address, stride, which words are written, named target) is read off the listing; claims the
listing does not show (axes, meaning, sortedness) are dropped or restated as listing facts. A script verifier of
countable claims (T8 harvest item) catches the residue. Never let a comment assert a meaning without >= 3 datapoints
(C0017).
