# Ghidra headless refuses project paths with a dotted element

## Symptom
`analyzeHeadless` (Ghidra 12.1.4) refuses to create or open a project when any element of the project path starts
with `.` (for example a scratch clone under `.run/` or `.cache/`). A fresh clone placed under a dotted folder cannot
run `make build` (the listing step needs the Ghidra project); on error the .bat ends with "Press any key to continue"
(it did not hang under `tools/run.sh --bg`).

## Fix
- Put scratch clones and their Ghidra projects on a dot-free path (the contract script uses `<repo parent>/_contract/<ts>`).
- Or keep the clone where it is and point the project elsewhere: env `MMTT96_GHIDRA_PROJ=<dot-free dir>`; `scripts/ghidra/db.py`
  refuses a dotted project path by name instead of failing deep inside Ghidra.

## Evidence
Phase 1.8 T1 fresh-clone probe (clone under `.run/contract/probe` could not build); T2 override proven by a cold
clone under a dotted parent with the override (build OK, health 9/9).
