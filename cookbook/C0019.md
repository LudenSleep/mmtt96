# Loading a project script whose name collides with a stdlib module

Problem: a project script named like a stdlib module (here `encodings`) cannot be imported by name from another
script or test: the stdlib module is already loaded at interpreter startup and wins. (C0001 covers scratch names.)

Technique:
- Load it by path: `importlib.util.spec_from_file_location("<alias>", path)`, then `module_from_spec` and
  `spec.loader.exec_module`.
- Or choose a non-colliding name when the script is created.

Origin: phase 1.6/T5 (scripts/census/encodings.py).
