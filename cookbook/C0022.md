# Neutral RAM names spill over: name RAM before writing comments

Symptom: naming the RAM operands of one region lowers the raw-operand count of many other regions; in-region closeness
understates the value of a naming pass.

Cause: game RAM is shared; a neutral `ram_FFxxxx` row renders at every use in every region (the renderer names by
address, not by region).

Fix: sweep neutral RAM rows first, globally, by script (operand census of all listings, size = widest access width), then
comment. Phase 1.7 wave 1: each large region's RAM rows fixed about 7x as many raw operands elsewhere (global named_ops
4428 -> 6203 from six regions). Measure progress on global raw/nameable counts, not per region.
