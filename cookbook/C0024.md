# A code name equal to a region id double-defines the label

Symptom: AS build fails with a double definition after a routine name is registered for an address that is also the
start of a region whose wrapper label has the same name (e.g. a call target that is region `imp_decrunch`).

Cause: `split.py` emits the region wrapper label `<id>:` and `names.inc` also emits `<name> equ $addr`.

Fix: when a code name equals a region id, emit no equ (the region label defines it) and assert the address in main.asm
(`if <name> <> $<addr6>` -> error), so a wrong-address row still fails the build; prove with a planted wrong address.
Gotcha: the propagate call that introduced the double define passed its own build gate; the next calls failed.
