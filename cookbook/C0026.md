# CRLF checkouts under core.autocrlf=true without .gitattributes

Symptom: on Windows with `core.autocrlf=true` and no `.gitattributes`, `git checkout` / clone writes CRLF into
files the index stores as LF; LF-strict readers (here `scripts/ghidra/db.py`) refuse them.

Fix:
- track `.gitattributes` with `* text=auto eol=lf` plus `binary` exceptions;
- `git add --renormalize .` and commit;
- prove it: a fresh clone shows `w/lf` in `git ls-files --eol`, against a control clone made before the fix (`w/crlf`).

Readers may keep refusing CR; the checkout is what changes. Source: 1.7/T4.
