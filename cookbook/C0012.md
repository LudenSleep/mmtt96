# MAME read taps vanish after a memory remap

Problem: a Lua read tap installed once on the 68000 program space stops firing a few frames into boot
(observed around frame 13 in phase 1.5/T4) because the memory map is rebuilt; a "never read" result is then false.

Technique:
- Reinstall the read tap every frame (frame callback), or install it after the remap and assert it fires.
- Always run a positive control in the same session: tap a range a verified routine is known to read and require hits.
- Only a run whose positive control fired may report "0 reads" for a candidate range.
- Pair a forced run (inputs forced so the branch is taken) with an unforced control run; report hits per run (e.g. 3/3 vs 0).

Origin: phase 1.5/T4 (data-row verdicts; MAME 0.289).
