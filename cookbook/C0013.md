# Ghidra "Bad Instruction" on valid 68000 words: cross-check before calling bytes data

Problem: Ghidra 12.1.4 rejected some valid 68000 word-pair encodings as Bad Instruction; flow analysis stops
there, so following code is never disassembled and looks like data (phase 1.5/T4, region code_0419EE span).

Technique:
- Before classifying an un-disassembled span as data, sweep it with the second oracle
  (`scripts/oracle/boundaries.py --scope inferred`, Capstone 5.0.9 M68K_000).
- If Capstone decodes the words and execution evidence exists (MAME coverage or a forced run), it is code;
  record regions Ghidra cannot decode in `config/oracle/boundary_exceptions.tsv` so the boundary gate stays exact.
- Keep the exception list tied to region ids only; detail rows stay under `.run/`.
