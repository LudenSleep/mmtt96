# Headless Ghidra (analyzeHeadless) on Windows: traps

1. `analyzeHeadless.bat` breaks on `(` in any argument (`(v1.1) was unexpected at this time.`): copy inputs to a paren-free path (here `.run/ghidra/mmtt96.md`, ignored).
2. On error the .bat prompts `Press any key to continue`: always run it with stdin=DEVNULL or it hangs.
3. Its exit code is unreliable for script failures: have pre/post scripts write a success marker file last and check the marker.
4. Cheap probe: `-process` on a missing/empty project exits 1; `-import <empty dir> -noanalysis` creates/opens it and exits 0.
5. Thunk functions take the thunked function's name; mirroring them into a name-keyed export breaks the round trip. Skip thunks.
6. Export only owned annotations (USER_DEFINED/IMPORTED, non-default names), sorted, LF, UTF-8, so re-export is byte-identical.
Source: phase 1.2 T1, T4 (`scripts/ghidra/db.py`, Ghidra 12.1.4).
