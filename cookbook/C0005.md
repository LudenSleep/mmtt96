# MAME (0.289) debugger + Lua as a scripted 68000 oracle: traps

1. Lua debugger access needs `-debug -debugger none`; trace with `manager.machine.debugger:command("trace f,maincpu,noloop")` (`cpu.debug:trace` is nil in Lua).
2. Debugger expressions parse `a7` as a hex literal: address the 68k stack pointer as `sp`.
3. On m68000 a bp action `printf "...",pc` prints the instruction address +2 (bp 0x200 prints 202): bake the address into the printed text.
4. A breakpoint at the address the debugger just wrote into pc does not fire for that first instruction: let the preceding bp action do the entry work.
5. `soft_reset()` re-runs the autoboot Lua script while earlier frame callbacks persist: guard the script with a global.
6. A PC trace from reset logs PC 0 (the SSP fetch) and vector reads: filter the vector table before treating PCs as executed code.
7. Verify a software-list set with `-verifysoftlist <list>` (e.g. `megadriv`), not `-verifysoftware <set>`.
8. MAME writes `cfg/` and `nvram/` into the cwd: gitignore them or run from scratch.
Source: phase 1.2 T2-T4 (`scripts/oracle/mame.py`, `megadriv microm96`).
