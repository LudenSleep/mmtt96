# Sidecar names need renderer support for every addressing form the code uses

Symptom: adding RAM rows to the names sidecar changes nothing in the listing; closeness stays put.

Cause: the renderer only looked up a subset of forms; 68000 code addresses RAM through abs.l `$FFxxxxxx` (sign-extended)
and abs.w `$xxxx` (>= $8000 means $FFxxxx); in wave 1, 1062/1062 RAM abs.l operands were FF-high and none rendered.

Fix: render abs.l by the low 24 bits when the high byte is $FF and the low 24 >= $FF0000, abs.w by its sign-extended
address, emit RAM equates as 32-bit sign-extended values so AS reproduces the same encoding; check names-on vs
--no-names listings assemble identically (health pair `names`). Count before/after on one region before a bulk pass.
