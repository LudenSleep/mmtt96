# C0015 — 68000 read tap hit on a row's first word is prefetch, not a read

# A read tap firing once on a row's first word is prefetch, not a data read

Problem: on the 68000, a MAME read tap over a candidate row fires once on its first word, with PC sitting there,
when the preceding instruction ends at the row's start: that is the instruction prefetch, not a data read and not
proof the row executes.

Technique:
- Discard a single hit at the row's first word whose PC equals the row start (or the previous instruction's end).
- Count only hits beyond the first word, or with a PC inside verified code that addresses the row as data.
- Use breakpoints, not read taps, to prove execution.

Origin: phase 1.6/T1 (taps over 54 inferred rows showed only first-word prefetch hits).
