## Rationale
- Tracked manifest path is `config/manifest.retail.jsonl`, not `extracted/retail/manifest.jsonl`. Evidence: `config/firewall.txt:17-18` purges `extracted/` and `extracted/**`, so a tracked manifest there fails the audit, while an untracked one makes the CI audit (`.github/workflows/no-rom.yml:37-38`, no game data) exit 1 once promoted to `required:` (`audit_public.py:114`). The audit has no allow-rule kind (`:69`), so keeping the kit path means weakening the purge globs. Moving the manifest keeps the firewall at full strength and CI green. T1 replaces the `pending: extracted/retail/manifest.jsonl` line and drops the now-dead `.gitignore:20-21` exceptions. The generation done-criteria ("no-ROM CI green") forbid the local-only option.
- Region table as a committed TSV of offsets: offsets and kinds are metadata, not game bytes. Keeping the evidence beside each boundary makes the map reviewable. The generator stays a pure function of (ROM, TSV), which is what makes "a second run is identical" checkable by `--check` and `git diff`.
- Partition invariant: partition records are sorted, contiguous, non-empty and cover 0..0x100000 with residue zero (the kit's disc_audit idea, G19). Decoded records hang off their parent and sit outside the partition.
- No disassembler dependency this phase. T2 locates the Z80 driver by byte patterns (bus-request and Z80-RAM absolute operands near a copy loop) and by community documentation; capstone or Ghidra belong to phase 1.2's oracle. Delta of a new dependency: none needed for the milestone.
- `--check` flag (the one feature beyond generation): regenerates in memory and byte-compares with the tracked manifest. It is the ops doc's "verify against the committed manifest" line (docs/ops/ops-setup-decomp.md:29-30) and the milestone's identity proof without dirtying the tree.
- Placement in `scripts/`, not `tools/`. The house scope rule keeps product code out of `tools/` (the harness). docs/ops/ops-setup-decomp.md:59 names `tools/` from the kit template; T4 corrects that row. harness: the decomp-architect ops template points project tools at `tools/`, which collides with the PA scope rule (ProjectArchitect repo gotcha, not a task).
- `config/medium.sha1` carries both dumps' hashes, so the backup's bytes are forbidden too (cheap, closes a firewall gap).
- Effort high: T2 only (1 of 4). Its done-when rests on judging region boundaries and a compression format from byte evidence and outside reports; no test can arbitrate a boundary. T1, T3 and T4 have mechanical gates (partition assert, decode consumes exactly the region, audit exit codes).
- Task split: T1 builds the skeleton and the firewall promotion first, so the milestone path exists from day one and T2 and T3 only add TSV rows and decoders. T4 closes with docs and the negative controls (G25), with no coder.
- Decoder verification without an emulator: each blob decodes to exactly its own length field (or terminator), consuming exactly its region. The cross-check against the game's own decompressor via the emulator is phase 1.2's job (G1, G21), recorded as a quarantine flag (`status: inferred`) on each decoded record until then.

- Manifest record shapes (JSON, `sort_keys=True`, `separators=(",",":")`, LF, trailing newline, UTF-8 no BOM):
  - medium (line 1): `{"id":"medium","kind":"medium","path":"<rom file name>","size":1048576,"sha1":"e8ff…"}`
  - partition (sorted by start): `{"id":"r0000","kind":"vectors","start":"0x000000","end":"0x000100","size":256,"sha1":"…","status":"verified","evidence":"md-spec"}`; gaps → `kind:"unknown","status":"inferred","evidence":"gap"`; ids `r%04d` by position.
  - header facts ride as extra keys on the header partition record (`checksum_stored`, `checksum_computed`, `rom_end`, `reset_pc`, `region`, `serial`): a separate line without `sha1` would KeyError the audit (`:93`).
  - decoded (after partition, sorted by parent): `{"id":"d0007","kind":"decoded","parent":"r0007","format":"<fmt>","size":N,"sha1":"…","out":"extracted/retail/decoded/r0007.bin","status":"inferred"}`.
- Raw outputs (ignored): `extracted/retail/raw/<id>.bin` for kinds z80 and compressed; `extracted/retail/decoded/<id>.bin`.

## Risks
- No compression found or the format is undocumented and unreadable without a disassembler: T3 shrinks to "none found" (critic: supersede T3, record in T2's report) or T2 returns blocked and the decoder moves to after phase 1.2's oracle. The milestone does not depend on decoders.
- Z80 driver uploaded in pieces or itself compressed: T2 enters several `z80` rows or a `compressed` row with a `z80` decoded child; schema already allows it.
- Header checksum mismatch or rom_end ≠ 0x0FFFFF: recorded as a fact, not a failure. The v1.1 dump hash is the arbiter.
- The audit only catches whole-file matches: a partial copy of ROM bytes in a tracked file passes. Accepted kit limit, mitigated by the purge paths. Not this phase's to fix (harness-level audit).
- CI Python 3.12 vs local 3.11: scripts/extract is not run in CI; manifest.jsonl is parsed by the audit only.
- Line endings: Windows git autocrlf could rewrite the tracked manifest and break `--check`. T1 writes LF bytes, and if a diff appears adds `config/manifest.retail.jsonl -text` to `.gitattributes`.
