## Answer
1. clownassembler ALWAYS rewrites CMP/ADD/SUB/AND/OR with a literal source to CMPI/ADDI/SUBI/ANDI/ORI (ResolveInstructionAmbiguity, semantic.c). The CMP operand table has no OPERAND_LITERAL in its source list, so B07C cannot be produced. No option or syntax found that changes this (pedantic warning only). Lever ladder: none inside clownassembler; use `dc.w $B07C` + `dc.w imm` (or a macro) or fall back to AS.
2. AS (code68k.c DecodeADDSUBCMP): plain `cmp.w #1,d0` with Dn dest uses the 0xB000 form with the immediate EA, so B07C. CMPI form only for explicit CMPI/ADDI/SUBI (I_Variant) or non-Dn destinations (default case: 0x400|size<<6|Op<<8, CMP Op 1 -> 8). No switch found.
3. clownassembler movem pc-rel base looks correct (instr+4). AS also correct (RelPos = 4 set in DecodeMOVEM).
4. asm68k / 1990s assemblers: NOT FOUND.

## Findings
- semantic.c ResolveInstructionAmbiguity: each of OR/AND/ADD/SUB/CMP checks `instruction->operands[0].type == OPERAND_LITERAL` then WARN_ALIAS_AND_LOOP(OPCODE_xxxI, "CMP should be CMPI."); CMP check runs after the CMPA (An dest) check. Unconditional; the warning needs pedantic_warnings_enabled and warnings_enabled, the rewrite does not depend on them.
- Encoder: `case OPCODE_CMP: machine_code = 0xB000;` and the CMP table source mask lacks OPERAND_LITERAL; a literal source otherwise errors "First operand cannot be a literal."; `case OPCODE_CMPI: machine_code = 0x0C00;`.
- clownassembler movem: ProcessInstruction does AdvanceProgramCounter(state,2) for the opcode word; the OPERAND_REGISTER_LIST case advances 2 for the mask, and the mask is output first (operands_to_output[0]). Then OPERAND_PROGRAM_COUNTER_WITH_DISPLACEMENT does `value -= state->program_counter;` before the shared advance, so base = instr+4 = address of the displacement word. Correct. No known bug found (no issue search done beyond reading code; changelog URL guessed, 404).
- AS: DecodeADDSUBCMP header comment `0=SUB 1=CMP 2=ADD +4=..I +8=..A`; I_Variant: `WAsmCode[0] = 0x400 | (OpSize<<6) | (Op<<8) | Reg`; other: `0x9000 | ... | (Op<<13)`. DecodeMOVEM sets `RelPos = 4` before the memory operand; DecodeAdr does `HVal -= (EProgCounter() + RelPos)`. No Optimize/NoCMPI option seen in bytes 0-200000 of the file (last 62k unread; AddInstTable lines not seen).
