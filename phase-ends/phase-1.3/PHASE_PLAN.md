## Rationale
- Assembler: clownassembler v1.1.3 `clownassembler_asm68k.exe` (asm68k-compatible, Motorola syntax) for the baseline. Delta over the current toolset: nothing installed assembles; make + Python cannot emit a ROM without writing a toy assembler, which 1.7 would discard. Why it over the alternatives (R-pending reports `retriever-web-68000-assembler-choice-md-disasm.md`, `-all-data.md`): the only candidate with a tagged stable release, a raw Windows exe (131,072 B, no archive, no helper tool) and a per-asset sha256 on GitHub; AS (asl) ships only rolling, prunable snapshots and needs `p2bin`; vasm has no verified Windows binary and would need a C compiler; SN asm68k is proprietary with no pinnable source. Fallback (only if T1's probe shows no flat-binary output or no usable assertion directive): AS snapshot `asl-windows-x86_64-v1.4.2.20261012` zip with its bundled `p2bin`.
- Does 1.4 revisit the assembler? It pins it; it does not redo this phase. The all-data source uses only a dialect-neutral subset (`org`, labels, `dc.b $xx`, `include`) plus one boundary-assert form isolated in one generator function, so a swap in 1.4 is a generator flag and a Makefile variable. 1.4 decides the final assembler by instruction probes (branch sizing, absolute short, moveq); data bytes cannot arbitrate that, so no data-phase evidence is claimed for it.
- Layout (decided here, no judgment left to tasks): `asm/main.asm` (generated: `org 0`, then `include` lines in address order); one file per region row `asm/rom/<id>.asm` for every row outside the compressed run (vectors, header, code, data, z80, padding: 1255 files; 1.7's conversion unit is a region row, so a converted row replaces exactly one file); the 368 compressed rows in one file `asm/imp.asm` (labels `imp_NNN`; they stay data forever, as do both z80 rows). Each region file opens with its label `<id>:` and ends with a generated boundary assert (`current address == end`, assembler error otherwise). That is the "boundary check inside the build": in 1.7 a converted region that grows or shrinks fails at its own file, not at the final hash. `dc.b` lines of 16 bytes, uppercase hex, LF; deterministic output (stable order = regions.tsv order).
- Dump discovery and refusal: `scripts/build/split.py` imports `ROM_DEFAULT`, `ROM_SHA1`, `refuse`, `read_regions`, `sha1` from `scripts/extract/manifest.py` (no refactor: one source of truth for path and hash). The Makefile checks `$(ROM)` exists before calling the splitter and prints `make: no ROM dump at <path>; copy your own dump there (see docs/ops/ops-setup-decomp.md)` and exits 2; split.py also refuses a wrong SHA-1 (exit 2). CI never reaches it (audit only).
- Make graph: `asm/.stamp` ← `$(ROM)`, `config/regions.retail.tsv`, `scripts/build/split.py`; `build/mmtt96.bin` ← stamp + `$(ASM)` exe; `build` = assemble, then `sha1sum -c config/check.retail.sha` (Git bash and Linux both ship `sha1sum`; no new script). `expected` = copy of a green `build/mmtt96.bin` into `expected/` (the baseline later phases diff against). `clean` removes `asm/` and `build/` only (never `disks/`, `ghidra/`, `expected/`; G18). Variables `PY`, `ROM`, `ASM`, `REGIONS` overridable on the command line (negative controls use them).
- Contract file `config/check.retail.sha`: one sha1sum line `e8ff759679a0df2b3f9ece37ef686f248d3cf37b  build/mmtt96.bin`; promotion edits firewall.txt:37 `pending:` → `required:` and drops the TODO.
