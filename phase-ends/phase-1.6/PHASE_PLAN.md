## Rationale
- Order: T1 (region fixes) first, because re-kinding V10 rows and moving code_0186A0 changes the verified code set every later scan denominates over (signatures, names, encoding forms). T2 (signatures) and T3 (name layer in the build) are independent machinery; T4 uses both on the first labelled routine; T5 (encoding coverage) runs on the final code set; T6 closes. Strictly sequential: one expert at a time keeps `asm/src`, `.run/ghidra/` and the Ghidra db free of races (pairs.py srcform empties `asm/src` at exit).
- Signature granularity: per Ghidra function body (entry from `functions.tsv`/seed export, end = next function entry or region end, clipped to the region) plus region rows. Three layers, as the kit names them: exact (sha1 of bytes), normalised (Capstone decode with absolute addresses, branch/PC displacements and immediates that are addresses masked; opcode, size and register fields kept), sequence (mnemonic-class skeleton, the census `sweep`/`mclass` notion). Exact and normalised groups propagate names; sequence groups are reported as families (candidates, not auto-named). Reason: hand-written code repeats by copy-paste with different absolute targets; normalised catches those; skeleton-only matches are too loose to name blind (G6, G62).
- Propagation contract (fail-closed): a name given to one member of a group is written to every member only if every member passes its byte gate (its region converted to named listing source, `make build` hash OK, `db.py listing` self-check `match`); any failure refuses the whole group and leaves the registry unchanged. The registry row stores the group id, the layer and the member's normalised-signature hash; the `signatures` health pair recomputes them and fails on drift (a registered member whose bytes or signature no longer match).
- Name rendering: names live in tracked TSVs under `config/names/` (new): `ram.tsv` (RAM/IO variables), `structs.tsv` (struct fields), `routines.tsv` (code/table names from propagation). `split.py` generates `asm/names.inc` (equates) and includes it after `AS_HEADER` in `main.asm`; the `db.py` self-check wrapper includes it too; `db.py listing` renders a matching absolute operand as the name. The exact high byte and size of the original operand must survive (the original may encode `$00FFxxxx` or `$FFFFxxxx` long forms, and abs.w sign-extends): the converter emits the name only when the equate reproduces the same encoding, otherwise raw hex, and the byte gate is the arbiter. Routine names: in-region definitions stay labels emitted at the entry; cross-region references use the name; a build-time assert `if <name> <> $addr` per code name fails closed if a label and the registry disagree. symbols.tsv mirrors ROM-address names (source `pa-names`) so Ghidra shows them; RAM names enter the mirror only if the Ghidra program has a RAM block (T3 checks; otherwise recorded as a gotcha, the TSV is the source of truth).
- Struct layer, minimal and evidence-based: at least one struct (>= 2 fields with offsets and widths proven by the bytes and by an oracle read/write observation) from the first labelled routine, rendered as `base+field` expressions on absolute operands. Field naming through `d16(An)` needs register-value tracking and belongs to 1.7/1.9; recorded, not built.
- Names are evidence-based (G62, G6): every `ram.tsv`/`routines.tsv` row has an `evidence` column pointing to a claim id, oracle datapoint file, region id or task log; a name with no evidence is a neutral `ram_FFC220`-style placeholder, which still counts toward listings using names. Prefix convention `v_` (RAM variable), `io_` (I/O register), `s_` (struct), routine names lower_snake: never a bare mnemonic word (asm_leak caution).
- Encoding coverage: a "form" = mnemonic + size suffix + per-operand addressing mode (Motorola `<ea>` modes: Dn, An, (An), (An)+, -(An), d16(An), d8(An,Xn), abs.w, abs.l, d16(PC), d8(PC,Xn), #imm, plus CCR/SR/USP/reglist), counted over Capstone decodes of every verified code region (independent of the Ghidra listing text). `docs/encoding-map.md` gains a coverage section: per form class, evidence = a probe id (`.run/` probe recorded in a task log) or a verified region id whose build is byte-gated (srcform covers every verified region, so a region id is sufficient evidence for a plain form; disagreement classes A-E keep their probe evidence). Tracked doc carries only form names, counts and region ids (firewall). The scanner fails on any form missing from the map and on a planted unmapped form. It is an `asm_leak`-style rung, not a pair: there is no second independent answer to "is it in the doc".
- `names` pair: two independent routes to the same ROM: listing build with names rendered vs listing build with names disabled (raw hex); both must hash OK and the name build must actually contain names (count > 0, the C0010 lesson: prove the hook is live). Planted: a deliberately wrong equate value must make the pair fire.
- Effort: T1 is `effort: high` (expert-fable class; not installed on this tier, runs on expert-opus55 at high effort): its done-when rests on reading proof from evidence (whether 22928 never-read bytes split, and where code_0186A0 really starts, with >= 3 datapoints per verdict); no test arbitrates a kind/split verdict, the byte gate only proves the bytes. All others are medium: their done-whens are machine-checked (hashes, fixtures, planted controls).
- Review: T4 `review: yes`: the developer sees the first named routine, its repeats and the first RAM/struct names (naming is the product's readable surface). No other task needs sifting.
- Tooling: no new dependency; Capstone 5.0.9 and the Ghidra headless path already exist. New scripts are `scripts/census/signatures.py` and `scripts/census/encodings.py`; both justified in their task (three-line rule): census groups whole regions only and has no operand masking; nothing scans forms.

- Ghidra function bodies are not contiguous or overrun region ends: detection = T2 coverage assert (unowned bytes counted); fallback = window signatures from call targets (`jsr`/`bsr` entries from seed refs) clipped at the next entry.
- Equate rendering changes an encoding (abs.l high byte $00 vs $FF, abs.w sign extension, AS optimising a symbolic operand differently from a literal, forward-reference sizing): detection = self-check and `names` pair; mitigation = equates defined before use (names.inc first), explicit size suffixes kept, raw hex fallback per operand. Class E (`0.w(An)`) and PC-relative stay as 1.4 wrote them.
- T1 re-split moves region boundaries: breaks census fixture expectations or the mirror pair; detection = verify chain; revert the TSV edit and keep the row inferred with the blocker named.
- `make health` grows past 285 s with two pairs and a rung: always run detached through run.sh with `--max 280`, one call per wait.
- Ghidra program without a RAM memory block: RAM names cannot mirror; TSV stays source of truth (gotcha, not a task).
- Card cap: any card line must be paid for by a trim in the same task (T6).
