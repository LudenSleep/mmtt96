# T24.c3 — wave_gate repair after B013 (c2)

## Cause
- c2 (ad0f119) added 3 rows to `config/names/routines.tsv` at region entries, named after the region ids:
  `0x01398E img_layout_load`, `0x015918 z80_upload_driver`, `0x01FA50 vdp_dma`.
- Named form: srcform pair `insn hash BAD; data hash BAD` (and incremental BAD). Isolated: dropping only those 3 rows -> `pair srcform: agree (... insn hash OK; data hash OK; bins equal)` (.run/logs/t24c3s1.log). Default `make build` was OK throughout (.run/logs/t24c3b0.log).
- Renaming to neutral `fn_<addr>` fixes srcform (.run/logs/t24c3s2.log) but `pair names: DISAGREE (... lines differ 1; unmirrored 3/2440)`: `config/ghidra/symbols.tsv` holds the region-id names as functions (R1.1-002); `db.py mirror` would rename those Ghidra functions to fn_*, not wanted.
- Fix: drop the 3 rows (the pre-c2 state, green at e6f713c). Only change: 3 deleted lines in routines.tsv.

## Evidence kept
- Dropped rows saved verbatim: `.run/t24/c3_dropped_rows.tsv` (scratch, ignored). Evidence text (col 8):
  - 0x01398E: region id name; unresolved: sets ram_FFCF98 to -1, then as fn_013994 (img_layout_load); settle with the region wave of code_0139B0
  - 0x015918: region id name; listing: copies region z80_driver into Z80 RAM between Z80 reset and bus steps, then polls a Z80 byte; upload verified by config/maps/ram.tsv z80_ram_after_upload
  - 0x01FA50: region id name; listing: Z80 bus held, VDP regs 19-23 loaded with length, source, 7F hex, VRAM write cmd with DMA bit; eight callers incl. code_01FA38
- Same facts already in `config/ghidra/comments.tsv` plates (0x01398E, 0x015918, 0x01FA50); comments untouched.
- generalizable: a routines.tsv row at a region entry whose name equals the region id breaks srcform hashes; a neutral name there breaks pair names (unmirrored). Region-entry names live in symbols.tsv/regions only.
