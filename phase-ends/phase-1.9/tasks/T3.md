Decisions:
- binding: a hardware constant enters `hw.tsv` only with `published-doc: <source>` evidence (basereg rows: `rom:` evidence, and constants.py checks the invariant); game constants go to `consts.tsv` only with >= 3 datapoints or a confirmed mechanics claim.
- binding: the in-scope set is "an immediate stored or bit-tested at a HW_PORTS address, resolved through absolute operands or a tracked port base"; constants.py exits 1 on any raw member. The vdp data port, PSG (C00011), J-Cart and the Z80 RAM mailbox stay raw (data or game protocol, not hardware constants).
- a6 is a game-wide VDP base (`basereg_a6` = vdp_data): written only by `lea vdp_data` at 000308/0003E6, movem restore from (SP)+ and region `init`; constants.py `BASE` lines fail on any other write.
- Access-command words: a word pair (first then second word, both immediate, both at vdp_ctrl) renders as `vdp_cmd_hi/lo($adr,<code name>)`; a lone word renders with numeric address and code (its other half is computed, so the code is not knowable from it).
- Field decomposition is greedy (widest masks first) with an `|$<rest>` remainder; register values that are counts or addresses (autoinc, hint, window position, DMA source) render as `vdp_reg_X|$n`.
